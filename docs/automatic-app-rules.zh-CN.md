# 按名称自动放行应用

[English](automatic-app-rules.md)

此分支为自定义规则编辑器增加了“自动匹配”页，支持按照可执行文件名称匹配应用，并附加安装目录、有效签名发布者条件。

## 构建与验证

此版本基于 Simplewall 3.8.5 后的开发提交
`d6fa5dfa51ed3bcc7595f54cfc8fdfdee82a2d48`，使用公开的 routine SDK
`2f7ce6a228dbbaa7295b9635ab971d2768a0ae9b`。其功能与上游 3.9.1 有差异，
上游自动更新已关闭。

GitHub Actions 工作流构建完整 Windows x64 程序，并执行匹配器、图形规则编辑器、
规则范围和 WFP 集成检查；结果以对应工作流运行记录为准。切换版本前请备份配置。
检查使用合成配置和隔离的测试环境，尚不覆盖所有配置格式。

## 如何使用

1. 在自定义规则编辑器中新建一条“放行”规则，按需要设置出站或入站、协议、地址和端口。
2. 打开“自动匹配”页，填写包含 `.exe` 后缀的文件名，例如 `example.exe`。
3. 按需要填写安装目录、发布者。填写的自动匹配条件必须全部满足。
4. 启用并保存规则。

| 条件 | 示例 | 匹配方式 |
| --- | --- | --- |
| 可执行文件名称 | `example.exe` | 完整文件名，不区分大小写；不支持通配符 |
| 安装目录，可选 | `C:\Program Files\Example` | 包含子目录；比较解析后的实际路径及目录边界 |
| 有效签名发布者，可选 | `Example Software Ltd.` | 必须通过 Windows 签名验证，并与签名证书的发布者通用名称完全匹配，不区分大小写 |

示例发布者是占位名称。这里的“名称”指可执行文件名，不是“已安装的应用”列表中的产品名称，也不是文件描述。

目录必须是本地盘符的绝对路径。不支持 UNC、设备路径、环境变量表达式、相对路径或通配符。`C:\Apps2` 不属于 `C:\Apps`；指向指定目录外部的目录联接或符号链接也不会满足该目录条件。

保存、启用或重建规则时，会检查 Simplewall 已知的程序。Simplewall 运行期间，一个新路径首次被它的默认策略阻止时，也会尝试匹配；该程序可能需要重试首次连接。此功能不扫描全盘，不自动匹配服务、商店应用、WSL 身份或网络路径。

## 与手动规则的关系

“应用”页的手动选择与自动匹配结果取并集。若只想放行满足自动条件的程序，请保留空的手动选择列表。

自动规则没有匹配结果时，不会扩大成全局放行。清空已有自动条件、且没有手动选中的应用时，规则会保持禁用并给出提示。

应用属性增加了“从自动放行规则中排除”选项。手动阻止应用也会设置该排除状态，防止下一次连接又被名称规则放行；手动允许会清除该排除状态。排除状态仅影响自动匹配，独立存在的手动放行权限仍单独生效。

## 发布者条件的边界

发布者来自通过 `WinVerifyTrust` 验证的嵌入式 Authenticode 签名，不使用可随意修改的 `CompanyName` 文件版本信息。仅有编录签名（catalog signature）的文件不在此匹配器的支持范围内。

验证要求证书链吊销检查通过，根证书除外。为避免匹配时阻塞在在线查询上，生产匹配器仅使用本机缓存的证书及吊销信息。信息缺失、状态未知、离线或已吊销时会拒绝匹配，因此一个正确签名的程序也可能因本机缓存尚未准备好而继续被阻止。

**这些条件在加入路径或重建规则时检查。生成的 WFP 规则仍然按应用路径生效，并非每次连接都重新检查签名。** 同一路径上的文件被替换后，此功能不会持续监控其签名身份；上游已有的文件变化监控选项是独立机制。

## 配置与验证

自动规则保存于独立的 `rules_auto` 段，自动得出的应用集合不会写成手动放行列表。这样可避免旧版 Simplewall 把它误读成全局规则。不过旧版不支持此功能，保存配置时可能丢弃该段，切换版本前应保留配置备份。

便携回归测试：

```sh
export CC=clang
python3 tests/autoallow_scope_test.py
python3 tests/autoallow_xml_presence_test.py
python3 tests/autoallow_revoke_test.py
python3 tests/autoallow_warning_test.py
python3 tests/autoallow_main_test.py
python3 tests/profile_environment_test.py
python3 tests/autoallow_messages_security_test.py
```

撤销测试会对实际删除函数注入事务开始失败、过滤器删除失败和事务提交失败，检查失败时仍保留过滤器标识并恢复保护状态。

Windows 独立匹配器测试：在 Visual Studio x64 开发者命令提示符中运行：

```bat
cl /nologo /W4 /WX /DUNICODE /D_UNICODE /Fe:autoallow_match_test.exe tests\autoallow_match_test.c src\autoallow_match.c
autoallow_match_test.exe "C:\Program Files\PowerShell\7\pwsh.exe"
```

测试参数必须指向可信且具有嵌入式签名的可执行文件。测试会在线预热该签名的验证缓存，再调用实际的缓存验证逻辑；它也检查无签名、签名不符、文件被修改和目录边界等情况。无法创建符号链接时，该项明确报告跳过。

Windows 集成测试覆盖过滤器安装、配置重载及受限的本地连接；图形测试检查规则编辑和保存。
首次阻止后的发现和手动排除仍需单独进行完整防火墙验证。
